{% blocktrans %} Unser UI Framework bietet nicht nur eine reihe von nützlichen Komponenten, sondern lässt sich auch vollkommen nach allen Wünschen anpassen. Farben und immer wiederkehrende Elemente, wie das Aussehen von Überschriften lassen sich an nur einer Stelle anpassen und sofort passt sich das Design an. Es lassen sich aber auch neue Komponenten hinzufügen und bestehende Komponenten anpassen. Sollte also eine Komponente nicht komplett passen, lässt sich diese mit relativ wenig Aufwand entsprechende anpassen. {% endblocktrans%}

{% trans "In den folgenden Abschnitten werden die unterschiedlichen Möglichkeiten der Anpassung beschrieben." %}

{% trans "Theming (anpassen ans Corporate Design)" %}

{% blocktrans with tailwind='TailwindCSS'|safe %} Unser UI Framework verwendet {{ tailwind }} für das Styling. Tailwind verwendet eine sog. input.css Datei, in welcher sich ein Theme aufbauen lässt. Darunter fällt die Definition von grundlegenden Eigenschaften wie Farben, Schriftgrößen oder Fonts, aber auch Custom-CSS-Klassen erstellen oder Animationen lassen sich dort definieren. Dank Tailwinds Preflight Funktion lassen sich auch Standards definieren, wodurch bestimmte Elemente zum Beispiel Überschriften immer gleich aussehen ohne das dafür überhaupt eine Klasse im HTML-Code angegeben werden muss. Die einzelnen Möglichkeiten und Bereiche der input.css werden in den nächsten Abschnitten näher erläutert. {% endblocktrans %}

{% blocktrans with input='insight_ui/utils/input.css'|safe %} Das Standard-Theme des Insight-UI Frameworks befindet sich in der Datei {{ input }}. {% endblocktrans %}

{% trans "Setup" %}

{% blocktrans with tailwind_cli='django-tailwind-cli'|safe %} Um das Theming anpassen zu können, müssen zuvor ein paar Schritte durchgeführt werden. Da unser Framework, TailwindCSS verwendet muss ein Tailwind Compiler installiert werden, am einfachsten geht dies über die {{ tailwind_cli }}. {% endblocktrans %}

{% blocktrans with uv='uv'|safe uv_add='uv add django-tailwind-cli'|safe %} Zuerst muss die django-tailwind-cli installiert werden, zum Beispiel über {{ uv }} mit {{ uv_add }}. {% endblocktrans %}

{% blocktrans with installed_apps='INSTALLED_APPS'|safe %} Anschließend muss django-tailwind-cli zu den {{ installed_apps }} hinzugefügt werden. {% endblocktrans %}

{# fmt:off #} INSTALLED_APPS = [ # ... "django_tailwind_cli", # ... ] {# fmt:on #}

{% trans "Damit der Compiler weiß wo die entsprechenden Dateien zu finden sind, müssen ein paar Settings gesetzt werden." %}

  • STATICFILES_DIRS: {% trans "Der Pfad zu den Staticfiles muss definiert werden." %}
  • TAILWIND_CLI_SRC_CSS: {% blocktrans with input='input.css'|safe %}Der Pfad zu der {{ input }}, welche die Theme Konfiguration enthält (dazu später mehr).{% endblocktrans %}
  • TAILWIND_CLI_DIST_CSS: {% trans "Der Pfad wo das generierte Stylesheet gespeichert werden soll." %}
  • TAILWIND_CLI_AUTOMATIC_DOWNLOAD: {% trans "Wir empfehlen das automatische Updaten des Tailwind-Compilers auszuschalten, da es zum einen immer mehr Speicherplatz verbraucht und zum anderen bei Fehlerhaften Downloads zu keinen Fehlermeldungen kommt." %}
{# fmt:off #} # Configure static files directory STATICFILES_DIRS = [BASE_DIR / <path/to/static_dir>] # Tailwind source file TAILWIND_CLI_SRC_CSS = BASE_DIR / ".venv/Lib/site-packages/insight_ui/static/insight_ui/css/input.css" # Tailwind dist file TAILWIND_CLI_DIST_CSS = "insight_ui/css/tailwind.css" # Prevent automatic updating (recommended) # This is a silent process that can lead to silent problems if the process is terminated too quickly. TAILWIND_CLI_AUTOMATIC_DOWNLOAD = False {# fmt:on #}

{% trans "Im Anschluss muss einmal das Setup der django-tailwind-cli durchgeführt werden, dabei wird auch die Tailwind-CLI heruntergeladen (~120MB)." %}

python manage.py tailwind setup

{% blocktrans with runserver='runserver'|safe tailwind='tailwind'|safe %} Danach kann der Entwicklungsserver gestartet werden, nur diesmal muss vor dem {{ runserver }} noch {{ tailwind }} stehen. {% endblocktrans %}

python manage.py tailwind runserver

{% trans "Customization" %}

{% blocktrans with settings='settings.py'|safe %} Um das Theming anzupassen muss diese Datei kopiert werden und anschließend in der Konfiguration von Insight-UI in den {{ settings }} angeben werden. {% endblocktrans %}

TAILWIND_CLI_SRC_CSS = "my-path/to/input.css"

{% blocktrans with insight_ui='Insight-UI'|safe %} In dieser muss der Pfad zu den {{ insight_ui }} Templates angepasst werden: {% endblocktrans %}

@source "../templates/insight_ui/";

ersetzen durch:

@source ".venv/Lib/site-packages/insight_ui/templates/insight_ui";

{% blocktrans with setup='python manage.py tailwind setup'|safe %} Anschließend muss {{ setup }} ausgeführt werden. {% endblocktrans %}

{% trans "Inhalt der input.css" %}

{% trans "Die Datei enthält die folgenden Komponenten, alle zusammen ergeben das Theme." %}

{% blocktrans with import='@import'|safe %} In der ersten Zeile befindet sich der {{ import }} für Tailwind, dieser wird benötigt, damit Tailwind aus dieser Datei, später das entsprechende Stylesheet generieren kann. {% endblocktrans %}

@import "tailwindcss";

{% blocktrans with source='@source'|safe %} In der nächsten Zeile befindet sich eine {{ source }} Direktive. Diese sagt Tailwind, wo es nach den Template Dateien suchen soll, um die CSS-Tags, welche dort verwendet werden zu finden. I.d.R sollte Tailwind von sich aus alle Projekt spezifischen Templates finden, nur externe Pakete machen ab und zu Probleme, daher steht hier auch der Pfad zu unseren Templates. {% endblocktrans %}

@source "../templates/insight_ui/";

{% trans "Die nächste Zeile wird benötigt für den wechseln zwischen Hell/Dunkel." %}

@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));

{% blocktrans with font='Atkinson Hyperlegible'|safe %} Von Hause aus, verwendet Insight-UI den Font {{ font }}. Dabei handelt es sich um kein standard System-Font, weshalb dieser explizit angegeben werden muss. Sollte ein anderen Font gewünscht sein, kann dieser an der Stelle ausgetauscht oder ergänzt werden. Der Pfad zum Font ist relative zu der input.css, also der Datei in welcher das definiert wird. {% endblocktrans %}

{# fmt:off #} @font-face { font-family: "insight-ui"; src: url("../font/AtkinsonHyperlegibleNext-VariableFont_wght.ttf"); } {# fmt:on #}

{% blocktrans with theme='@theme'|safe %} Das ist ja alles ganz nett, aber wo sind die Farben? Nun, bis auf den Font sind die bisherigen Schritte notwendig und sollten auch nicht ohne Grund verändert werden. Das eigentliche Theme kommt jetzt erst. Passenderweise wird der Block mit {{ theme }} deklariert. In diesem Block werden all die Theme spezifischen Variablen definiert. Darunter auch Farben. {% endblocktrans %}

{% blocktrans with font='--font-sans: "insight-ui", sans-serif;'|safe %} Doch zunächst nochmal der Font. In dem Theme-Block lässt sich auch ein Default-Font einstellen, welcher für alle Texte im gesamten Projekt verwendet wird, ohne in jedes mal explizit angeben zu müssen. Die Direktive {{ font }} sagt, dass jeder Text, der keine Serifen besitzen soll, den Font Inter verwenden soll. {% endblocktrans%}

{% trans "Todo: mehrere Fonts definieren." %}

{# fmt:off #} @theme { --font-sans: "Inter", sans-serif; --color-insight-primary: #3b82f6; ... --color-insight-text-link-hover: #93c5fd; --animate-blink: blink 2s step-start infinite; @keyframes blink { 0%, 100% { opacity: 0; } 50% { opacity: 100; } } } {# fmt:on #}

{% blocktrans with caption='<h>'|safe %} Während die Variablen welche in dem Theme-Block definiert wurden, sich manuell auf Elemente anwenden lassen und jeweils eine Eigenschaft anpassen, können auch komplette Designs für bestimmte HTML-Tags vordefiniert werden. Dies funktioniert mittels Tailwinds Preflight Modul. Dieses entfernt vor allem alle Default Styles der HTML-Elemente wodurch beispielsweise alle {{ caption }} gleich aussehen. Das passiert, u.a. um die verschiedenen Browser-Defaults zu entfernen, damit die Seite in jedem Browser gleich aussieht. Zum anderen lassen sich darüber aber auch direkt Styles für bestimmte Elemente hinzufügen. {% endblocktrans %}

{% blocktrans with button='button:not(:disabled), [role="button"]:not(:disabled) { cursor: pointer; }'|safe pointer='pointer'|safe %} Die Zeile {{ button }} sorgt bspw. dafür, dass alle Buttons ein {{ pointer }} also ein Hand-Cursor aufzeigen (seit Tailwind V.4.0 nicht mehr standard und deswegen hier angegeben). {% endblocktrans%}

{% blocktrans with caption='<h1>'|safe caption_red='<h1 class="text-red-500>'|safe %} Die direktive drunter für das {{ caption }} Tag, gibt an dass die dort aufgelistet CSS-Klassen auf jedes {{ caption }} Tag angewendet werden sollen. Dadurch müssen nicht bei jedem Tag, diese Klassen manuell hinzugefügt werden. Sollte es mal zu ausnahmen kommen, können im Template trotzdem noch weitere CSS-klassen ergänzt werden oder überschrieben werden. So werden Überschriften mit {{ caption_red }} trotzdem in Rot dargestellt. {% endblocktrans %}

{# fmt:off #} @layer base { button:not(:disabled), [role="button"]:not(:disabled) { cursor: pointer; } h1 { @apply text-3xl font-bold text-insight-text-primary dark:text-white mb-4; } } {# fmt:on #}

{% blocktrans with components='components'|safe %} Der nächste Block heißt {{ components }} und enthält sozusagen Custom-CSS-Klassen. Warum keine Custom-CSS-Klassen in dem eigentlichen Stylesheet? Theoretisch gibt es kein konventionelles Stylesheet, da dieses von Tailwind erzeugt wird und zwar jedes mal wenn sich etwas an den Templates ändert. Insofern der Tailwind-Compiler läuft. Dabei wird jedes mal die gesamte Datei neu erstellt und alle manuell hinzugefügten Klassen gehen verloren. Um trotzdem vorgefertigte Konstrukte verwenden zu können, ohne jedes mal zwanzig CSS-klassen kopieren zu müssen, lassen sich {{ components }} definieren. {% endblocktrans %}

{% blocktrans with button='<button class="btn btn-sm">'|safe apply='@apply'|safe %} In der input.css sind beispielsweise Komponenten für Buttons definiert. Diese können in den Templates wie eine normale CSS-Klasse verwendet werden {{ button }}. Die Syntax hat hierbei mit klassischen CSS wenig zu tun. Stattdessen werden per {{ apply }} die jeweiligen Tailwind-Klassen oder auch andere Custom-Klassen hinzugefügt. Ein Vorteil für alle die bisher mit Tailwind gearbeitet haben. {% endblocktrans %}

{# fmt:off #} @layer components { .btn { @apply flex gap-2 items-center justify-center border-2 rounded-sm text-white px-5 py-1.5; } ... } {# fmt:on #}

{% trans "Template überschreiben" %}

{% blocktrans with path='templates/insight_ui/components/'|safe %} Es besteht die Möglichkeit, die bereitgestellten Komponenten anzupassen. Dafür muss lediglich das entsprechende Template der Komponente in das eigene Projekt-Verzeichnis kopiert werden. Wichtig ist nur, dass das kopierte Template in diesem Pfad {{ path }} abgelegt wird. Das Verzeichnis muss sich im Root-Verzeichnis des Projektes befinden. {% endblocktrans %}

{% trans "Beispiel:" %}

{# fmt:off #} myapp/ └── templates/ │── insight_ui/ └── components/ └── navbar.html # Overwrites the standard Navbar-Template {# fmt:on #}
