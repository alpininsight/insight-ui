{% trans "Theming (adapting to a corporate design)" %}

{% blocktrans with tailwind='TailwindCSS'|safe %} Our UI framework uses {{ tailwind }} as its default styling implementation. Tailwind uses a so-called input.css file in which a theme can be built. This includes defining basic properties such as colors, font sizes or fonts, but also creating custom CSS classes or animations. Thanks to Tailwind's Preflight function, standards can also be defined so that certain elements such as headings always look the same without needing a class specified in the HTML code. The individual options and sections of the input.css are explained in more detail in the following sections. {% endblocktrans %}

{% blocktrans %} The public design contract is semantic: brand colors, status colors, text colors, surfaces, interaction states, and component behavior should stay meaningful even if the styling implementation changes in the future. {% endblocktrans %}

{% blocktrans with input='insight_ui/utils/input.css'|safe %} The default theme of the Insight UI framework is located in the file {{ input }}. {% endblocktrans %}

{% trans "Start with your corporate identity" %}

{% blocktrans with input='input.css'|safe theme='@theme'|safe %} The recommended starting point is to map your corporate identity to Insight UI's semantic tokens in {{ input }}. Put your brand colors, text colors, status colors, interaction states, and default font into the {{ theme }} block. Buttons, links, headings, forms, surfaces, and documentation examples then consume the same design decisions without changing every template. {% endblocktrans %}

  • {% trans "Use primary and secondary colors for the main brand actions and supporting accents." %}
  • {% trans "Use success, warning, danger, and info colors for product and system states." %}
  • {% trans "Use text tokens for primary content, secondary content, and links." %}
  • {% trans "Use component classes and template tags after the tokens are set, so the whole UI follows the same visual language." %}
{# fmt:off #} @theme { --font-sans: "Inter", sans-serif; --color-insight-primary: #0057b8; --color-insight-primary-hover: #0072ce; --color-insight-primary-active: #1d8fe3; --color-insight-secondary: #008578; --color-insight-secondary-hover: #00a992; --color-insight-secondary-active: #2cc8b4; --color-insight-success: #15803d; --color-insight-warning: #ca8a04; --color-insight-danger: #dc2626; --color-insight-info: #2563eb; --color-insight-text-primary: oklch(26.9% 0 0); --color-insight-text-secondary: oklch(55.6% 0 0); --color-insight-text-link: var(--color-insight-primary); --color-insight-text-link-hover: var(--color-insight-primary-hover); } {# fmt:on #}

{% blocktrans with input='input.css'|safe %} Change templates only when the structure, behavior, or component anatomy must change. For brand alignment, prefer {{ input }} first. {% endblocktrans %}

{% trans "Setup" %}

{% blocktrans with tailwind_cli='django-tailwind-cli'|safe %} To be able to customize the theming, a few steps need to be carried out first. Since our framework uses TailwindCSS, a Tailwind Compiler must be installed. This is most easily done via {{ tailwind_cli }}. {% endblocktrans %}

{% blocktrans with uv='uv'|safe uv_add='uv add django-tailwind-cli'|safe %} First, django-tailwind-cli must be installed, for example via {{ uv }} with {{ uv_add }}. {% endblocktrans %}

{% blocktrans with installed_apps='INSTALLED_APPS'|safe %} Then django-tailwind-cli must be added to the {{ installed_apps }}. {% endblocktrans %}

{# fmt:off #} INSTALLED_APPS = [ # ... "django_tailwind_cli", # ... ] {# fmt:on #}

{% trans "So that the compiler knows where to find the relevant files, a few settings need to be configured." %}

  • STATICFILES_DIRS: {% trans "The path to the static files must be defined." %}
  • TAILWIND_CLI_SRC_CSS: {% blocktrans with input='input.css'|safe %}The path to {{ input }}, which contains the theme configuration (more on this later).{% endblocktrans %}
  • TAILWIND_CLI_DIST_CSS: {% trans "The path where the generated stylesheet should be saved." %}
  • TAILWIND_CLI_AUTOMATIC_DOWNLOAD: {% trans "We recommend disabling the automatic updating of the Tailwind compiler, as it would consume more and more storage space and prevents error messages due to failed downloads." %}
{# fmt:off #} # Configure static files directory STATICFILES_DIRS = [BASE_DIR / <path/to/static_dir>] # Tailwind source file TAILWIND_CLI_SRC_CSS = BASE_DIR / ".venv/Lib/site-packages/insight_ui/static/insight_ui/css/input.css" # Tailwind dist file TAILWIND_CLI_DIST_CSS = "insight_ui/css/tailwind.css" # Prevent automatic updating (recommended) # This is a silent process that can lead to silent problems if the process is terminated too quickly. TAILWIND_CLI_AUTOMATIC_DOWNLOAD = False {# fmt:on #}

{% trans "Next, the setup of django-tailwind-cli must be run once, during which the Tailwind CLI is also downloaded (~120MB)." %}

python manage.py tailwind setup

{% blocktrans with runserver='runserver'|safe tailwind='tailwind'|safe %} After that, the development server can be started with %(tailwind)s, so this time {{ tailwind }} must be included before {{ runserver }}. {% endblocktrans %}

python manage.py tailwind runserver

{% trans "Contents of input.css" %}

{% trans "The file contains the following components, which together make up the theme." %}

{% blocktrans with import='@import'|safe %} The first line contains the {{ import }} for Tailwind. This is needed so that Tailwind can later generate the corresponding stylesheet from this file. {% endblocktrans %}

@import "tailwindcss";

{% blocktrans with source='@source'|safe %} The next line contains the {{ source }} directive. This tells Tailwind where to look for the template files to find the CSS tags used inside. Normally Tailwind should find all project-specific templates on its own, but external packages occasionally cause issues, which is why the path to our templates is also specified here. {% endblocktrans %}

@source "../templates/insight_ui/";

{% trans "The next line enables switching between light/dark mode." %}

@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));

{% blocktrans with font='Atkinson Hyperlegible'|safe %} By default, Insight UI uses the font {{ font }}. This is not a standard system font, which is why it must be specified explicitly. If a different font is desired, it can be replaced or supplemented here. The path to the font is relative to the input.css, i.e. the file in which it is defined. {% endblocktrans %}

{# fmt:off #} @font-face { font-family: "insight-ui"; src: url("../font/AtkinsonHyperlegibleNext-VariableFont_wght.ttf"); } {# fmt:on #}

{% blocktrans with theme='@theme'|safe %} That's all very nice, but where are the colors? Apart from the font, the previous steps are necessary and their settings should not be changed without reason. The actual theming comes now. Fittingly, the block is declared with {{ theme }}. In this block all theme-specific variables are defined, including colors. {% endblocktrans %}

{% blocktrans with font='--font-sans: "insight-ui", sans-serif;'|safe %} But first, the font again. In the theme block, a default font can also be set that is used for all text throughout the entire project without having to specify it each time. The directive {{ font }} causes any text without serifs to use for example the font Inter. {% endblocktrans%}

{# fmt:off #} @theme { --font-sans: "Inter", sans-serif; --color-insight-primary: #3b82f6; ... --color-insight-text-link-hover: #93c5fd; --animate-blink: blink 2s step-start infinite; @keyframes blink { 0%, 100% { opacity: 0; } 50% { opacity: 100; } } } {# fmt:on #}

{% blocktrans with caption='<h>'|safe %} While the variables defined in the theme block can be manually applied to elements to adjust individual properties, complete designs for specific HTML tags can also be predefined. This works via Tailwind's Preflight module, which removes all default styles from HTML elements so that for example all {{ caption }} look the same. This is done partly to remove various browser defaults so that the page looks the same in every browser, and also to directly add styles for specific elements. {% endblocktrans %}

{% blocktrans with button='button:not(:disabled), [role="button"]:not(:disabled) { cursor: pointer; }'|safe pointer='pointer'|safe %} The line {{ button }} ensures for example that all buttons show a {{ pointer }}, i.e. a hand cursor (no longer standard since Tailwind V.4.0 and therefore specified here). {% endblocktrans%}

{% blocktrans with caption='<h1>'|safe caption_red='<h1 class="text-insight-danger>'|safe %} The directive below for the {{ caption }} tag specifies that the CSS classes listed there should be applied to every %(caption)s tag. This means that these classes do not need to be added manually to each tag. If exceptions are wanted, additional CSS classes can still be added or overridden in the template. For example, headings with {{ caption_red }} will still be displayed in red. {% endblocktrans %}

{# fmt:off #} @layer base { button:not(:disabled), [role="button"]:not(:disabled) { cursor: pointer; } h1 { @apply text-3xl font-bold text-insight-text-primary dark:text-white mb-4; } } {# fmt:on #}

{% blocktrans with components='components'|safe %} The next block is called {{ components }} and contains custom CSS classes. Why are there no custom CSS classes in the actual stylesheet? There is technically no conventional stylesheet, since it is generated by Tailwind every time something changes in the templates, as long as the Tailwind compiler is running. Each time, the entire file is recreated and all manually added classes are lost. To still be able to use predefined constructs without having to copy CSS classes every time, {{ components }} can be defined. {% endblocktrans %}

{% blocktrans with button='<button class="btn btn-s">'|safe apply='@apply'|safe %} In the input.css, for example, components for buttons are defined. These can be used in templates like a normal CSS class {{ button }}. The syntax has little to do with classic CSS. Instead, the respective Tailwind classes or other custom classes are added via {{ apply }}. This is an advantage for anyone who has previously worked with Tailwind. {% endblocktrans %}

{# fmt:off #} @layer components { .btn { @apply flex gap-2 items-center justify-center border-2 border-transparent rounded-insight-control px-5 py-1.5 text-white transition-colors; } ... } {# fmt:on #}
